# Project instructions

- Read `prd.md` before implementing product features.
- Follow the stack and scope in `prd.md`; do not swap services without approval.
- Work in small stages and run typecheck, lint, and build after changes.
- Never put Supabase service-role keys or other secrets in frontend code or git.
- Never disable RLS to make a feature work.
- Do not deploy, change DNS, delete data, or run destructive commands without asking.
- Keep UI responsive and include loading, empty, error, and success states.
- If a requirement is unclear, choose a safe simple option and document the assumption.
- At the end of each stage, summarize changed files, checks, and remaining work.
